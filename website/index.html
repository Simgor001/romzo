Romzo

Route real-time messages by room ID. Rooms, tickets and channels live in the relay, so your app can stay a static page. Run the Go binary yourself, or start with the public node.

按房间号路由实时消息。房间、票据、频道都在中继侧，应用本身 可以只是一个静态页面。自己跑这个 Go 二进制，或先用公共节点。

Quick start

快速开始

Create a room on the public node:

对公共节点创建一个房间：

import { createRoom, buildInviteLink, RelaySession } from '@romzo/client';

const room = await createRoom('https://romzo.net', {
  game: 'example', players: 2, rules: ['draft']
});

const invite = buildInviteLink(room.descriptor.origin,
  room.descriptor.code, 'https://client.example.com/');
// https://client.example.com/#ABCD123XYZ@romzo.net

const session = await RelaySession.connect(
  'wss://romzo.net/ws', room.admission, room.transport);

await session.subscribe('game');

The public node takes no creation password. Private relays with CREATE_AUTH=password take { password } as the third argument. Guests join with joinRoom and a room code.

公共节点建房免密钥；开了 CREATE_AUTH=password 的私有节点， 第三个参数传 { password }。访客凭房号用 joinRoom 加入。

Typical uses

典型应用

Multiplayer games, shared whiteboards, room chat — anything that groups people by room and moves JSON in real time. The scenario logic lives in the client. The relay only ships room grouping and three fixed channels (discovery / lobby / game), the game channel allowing larger frames (256 KiB vs 16 KiB).

联机对战、协作白板、房间聊天——凡是要把一群人按房间分组、实时转发 JSON 的场景都适用。场景逻辑全在客户端；中继内置的只有房间分组和三个固定频道 （discovery / lobby / game），其中 game 频道 允许更大的单帧（256 KiB，其余 16 KiB）。

Self-host

自部署

Build the binary, generate a secrets file, then start it with Docker Compose:

构建二进制，生成密钥文件，然后用 Docker Compose 启动：

go build -trimpath -o relay .
relay init > .env.secrets
docker compose up --build -d

Put PUBLIC_ORIGIN and CLIENT_ORIGINS in .env. Do not change AUTH_SALT or TICKET_KEY across restarts, or recovery tickets stop working. Full deployment guide.

在 .env 里设置 PUBLIC_ORIGIN 与 CLIENT_ORIGINS。AUTH_SALT 和 TICKET_KEY 在重启之间不要更换，换了恢复票据会失效。 完整部署指南。
